# test-gate

Очередь для тяжёлых тестов на Mac, когда их запускают несколько ИИ-агентов
(Claude Code, Codex) одновременно.

**Проблема:** два-три агента параллельно запускают `yarn test`, Playwright и
интеграционные тесты с контейнерами. Память кончается, macOS показывает окно
«Завершить приложения», всё тормозит.

**Что делает test-gate:**

- `tg-run`: тяжёлые прогоны идут по очереди (по умолчанию по одному) на всю
  машину, во всех репозиториях и worktree. Ожидающий видит `QUEUED: position 2 of 3`.
- Не запускает тяжёлое, если давление памяти критическое или мало места под своп.
- После прогона добивает оставшиеся процессы (воркеры jest, браузеры).
- Хук для Claude Code не даёт агенту запустить тяжёлые тесты в обход очереди
  и подсказывает правильную команду.
- `tg-log` и `tg-measure` нужны для замеров: что на самом деле съедает память.
- `tg-status` и плагин для строки меню показывают, что сейчас идёт и кто ждёт.

Зависимостей нет, только то, что есть в macOS. `jq` желателен для хука и
установки (в macOS 15+ он уже есть).

> Статус: эксперимент. Скрипты проверены тестами в Linux, на macOS ещё не
> запускались. Если что-то падает, пришлите вывод.

## Установка

```bash
git clone https://github.com/iliakhlyzov/test-gate ~/.test-gate
```

```bash
~/.test-gate/install.sh --claude-hook
```

Команды появятся в `~/.local/bin`, а хук попадёт в `~/.claude/settings.json`
(рядом будет создана резервная копия). Если `~/.local/bin` нет в `PATH`,
установщик подскажет строку для `~/.zshrc`. Удаление: `install.sh --uninstall`.

Затем добавьте агентам инструкцию из [docs/agents.md](docs/agents.md) в
`~/.claude/CLAUDE.md` и `~/.codex/AGENTS.md`.

## Эксперимент: 3–5 дней

Цель: ноль окон «Завершить приложения» и понять, кто виноват.

**1. Включить логгер** (пишет состояние каждые 15 секунд):

```bash
tg-log start
```

Когда Mac начнёт тормозить или появится окно, отметьте момент:

```bash
tg-log mark "окно force quit"
```

**2. Замерить один прогон каждого типа** на спокойной машине:

```bash
tg-measure yarn test
```

```bash
tg-measure yarn playwright test
```

Покажет пик памяти всего дерева процессов, своп, VM Docker и процессы,
оставшиеся после прогона. Если один прогон занимает больше половины RAM,
одна очередь не спасёт: сначала ограничьте воркеров (см. ниже).

**3. Ограничить сами тесты.** В конфигах проекта:

```js
// jest.config.js
module.exports = { maxWorkers: 2, workerIdleMemoryLimit: '1GB' }
```

```js
// playwright.config.ts
export default defineConfig({ workers: 2 })
```

Для Docker Desktop ограничьте память (Settings → Resources), например 4–6 ГБ,
или перейдите на OrbStack (память освобождается динамически). Не отключайте
Ryuk у testcontainers: он убирает контейнеры за упавшими прогонами.

**4. Посмотреть итоги:**

```bash
tg-log summary
```

Пиковые своп и память, минимум свободного диска, моменты повышенного давления
с топом процессов, ваши отметки и статистика ожидания в очереди.

## Команды

| Команда | Что делает |
|---|---|
| `tg-run -- <cmd>` | тяжёлый прогон через очередь |
| `tg-run --light -- <cmd>` | без очереди, ждёт только при критическом давлении памяти |
| `tg-status` | что идёт и кто ждёт |
| `tg-log start` / `stop` / `status` | фоновый логгер |
| `tg-log mark [заметка]` | отметить момент зависания |
| `tg-log summary [дней]` | итоги по логам |
| `tg-measure <cmd>` | замер одного прогона |

Данные лежат в `~/Library/Application Support/test-gate/`, логи в подпапке `logs/`.

## Что считается тяжёлым (хук)

- **Тяжёлое, только через очередь:** `yarn test`, `npm test`, `npx jest`,
  `vitest run`, `playwright test`, скрипты `test:*`, `e2e*`, `integration*`,
  `make test`.
- **Лёгкое, без очереди:** прогон с явными файлами тестов,
  `yarn test src/a.test.ts`. Но если в команде есть e2e, integration или
  playwright, она всё равно тяжёлая.
- **Запрещено:** watch-режим (`--watch`, `--watchAll`).

Не уверен — считает тяжёлым. Настройка регулярками:
`TEST_GATE_HEAVY_SCRIPTS` (какие скрипты package.json считать тестами,
например добавить `build`) и `TEST_GATE_ALWAYS_HEAVY`.
Временно выключить хук: `TEST_GATE_HOOK=off`.

## Настройки tg-run

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `TEST_GATE_SLOTS` | 1 | сколько тяжёлых прогонов одновременно |
| `TEST_GATE_MAX_PRESSURE` | 2 | стартовать при давлении не выше: 1 normal, 2 warn, 4 critical |
| `TEST_GATE_MIN_DISK_GB` | 15 | минимум свободного места под своп |
| `TEST_GATE_MAX_WAIT` | 0 | сдаться через N секунд ожидания (выход с кодом 75), 0 = ждать всегда |
| `TEST_GATE_KILL_LEFTOVERS` | 1 | добивать оставшиеся процессы прогона |

## Строка меню

Установите [SwiftBar](https://github.com/swiftbar/SwiftBar) и сделайте
симлинк на плагин в папку плагинов SwiftBar:

```bash
ln -s ~/.test-gate/swiftbar/test-gate.5s.sh "<папка плагинов SwiftBar>/"
```

Иконка: 🟢/🟡/🔴 по давлению памяти, `▶1 ⏳2` означает 1 прогон идёт, 2 ждут.
В меню есть список прогонов и кнопка Stop для каждого.

## Ограничения

- Хук видит только команды Claude Code. Codex и ручные запуски очередь
  обходят, для них есть только инструкция агентам.
- Распознавание по тексту команды: `bash -c "yarn test"` или свой скрипт
  хук не узнает.
- Ожидание в очереди дольше таймаута команды агента (у Claude Code до 10
  минут) обрывает ожидание. Поэтому лучше запускать в фоне.
- Память считается по RSS, это приблизительно. VM Docker в замер прогона не входит.
- Логгер не переживает перезагрузку, после неё снова `tg-log start`.
